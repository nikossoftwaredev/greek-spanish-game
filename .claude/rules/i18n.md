# Language: Greek interface, Spanish content

- The interface is **Greek only** (`<html lang="el">`). There is no next-intl, no locale route segment and no `messages/` folder. UI strings are written directly in the components. If a second interface language is ever needed, re-introduce next-intl properly instead of adding ad-hoc string tables.
- Spanish is the **target language** and is data, not interface. It lives in `content/` and is always set in the serif (`font-es` utility, Alegreya). Greek and interface text use the sans (Manrope). Both fonts load the `greek` subset: keep it that way, Greek must never fall back to a system font.
- Greek is written in monotonic orthography, in a natural, friendly register aimed at an adult learner.
- Spanish text shown to the learner should be tappable (`TappableText`) wherever the Spanish is not itself the answer to a question. Never make the answer of an exercise tappable.
- Use `navigator`-independent date handling: dates are `YYYY-MM-DD` keys in the device's local time (`todayKey()`), never UTC slices.

## Writing content (`content/`)

The full schema and its writing rules are in `types/content.ts`. In short:

- Vocabulary is transcribed faithfully from the book's "Léxico" pages (spelling and accents exactly). Examples, drills and Greek explanations are **original**, never copied from the book.
- No em dashes, no `--` dashes, in any string.
- Ids are stable and globally unique (`u3-ciudad`). Never reuse or renumber an id: progress is stored against it.
- A cloze has exactly one `___`; a choice `answer` is one of its `options`; if more than one answer is correct, list them in `alternatives`. Run `pnpm validate:content` after every edit.
